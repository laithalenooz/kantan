簡単 kantan: simple, brief

Plan it. Approve it. Then let your tests decide.

A local web UI that drives the real claude CLI through one coding task at a time. It reads your repo and writes a plan. You say yes, or send it back with a note. Then a fresh agent implements it and kantan runs your tests until the exit code says they pass.

Get it on GitHub → How it works
# three commands, one process
bun install
bun run build
bun run server  # 127.0.0.1:3100

One task, one agent, one human gate.

It spawns the real claude binary rather than reimplementing an agent loop, so your CLAUDE.md, skills, plugins, hooks, settings and auth all load exactly as they do in your terminal. There is nothing to port and nothing to configure twice.

An agent reads your repository and writes a plan to docs/plans/. Then it stops. It has not touched your code yet.

You read it the way you would read a teammate's draft. Approve it, or send it back with a note and it plans again. Nothing else moves until you decide — this is the only step kantan cannot do without you, and that is the point.

A fresh agent implements the plan on its own kantan/<task> branch. Fresh, not the same conversation: that is what lets the two phases run different models without cold-starting the prompt cache.

kantan runs your test command and reads the exit code. Not the agent — the server. On a failure it refines and runs them again, escalating effort when the same failure repeats.

The task's checkbox is ticked and the branch is yours. The checkout returns to your base branch. If there was no test command to run, the screen says “Self-checked” rather than claiming a pass.

Three claims, and the code that backs each one.

Verification

The server runs your tests, not the agent.

kantan spawns your test command itself and branches on the exit code. Never on the agent reporting success. Verification from outside the agent cannot be talked out of.

Honesty

No screen claims a check it did not watch.

A project may have no test suite, and then the agent checks itself. kantan records which happened, and prints “Self-checked” — never an exit code, a tick, or the word passed. An older log reads “unknown”, never as a pass.

Scope

One run per project, and it says why.

Two agents can never share a working tree. A task that cannot start explains itself in a sentence instead of greying a button out.

What this is not.

Read this part first, because it is the whole design. Every one of these is a reaction to a tool that started well and drifted — the ceremony tends to grow faster than the usefulness.

  • ✕No agent org chart. No CEO, CTO or specialist personas.
  • ✕No autonomy. Nothing wakes itself up. No heartbeats, no routines, no schedulers.
  • ✕No multi-agent orchestration. If you want a fleet of agents negotiating with each other, this will disappoint you — deliberately.
  • ✕No tracker database. Markdown in your repo, or nothing.
  • ✕No worktree sprawl. One branch per task, one active run per project.

What we learned about claude -p, so you do not have to.

These cost real money to discover. Every script behind them is rerunnable in docs/probes/, so you can check rather than trust — and they are useful even if you never run kantan.

  • AskUserQuestion does not exist in -p mode. The agent asks in prose and exits subtype: success, so a question and a completion are indistinguishable by message type. Never infer completion from exit status.
  • --max-budget-usd bounds one process, not your run. Cost resets on every --resume, so a ceiling set per process silently restarts at each gate. Track the total yourself and pass ceiling − spent.
  • Switching models inside one conversation is a trap. It cold-starts the prompt cache and drops thinking blocks the new model cannot read. Switch between conversations instead — which is why kantan's plan and implement phases are two.
  • Hook events flood the stream. Roughly twenty system/hook_* messages arrive before the first real one. Filter at parse.

It works, and it is rough in places.

The pipeline runs end to end against the real binary, from one process on one port. 73 modules, 2,576 tests. The one skipped test is the live smoke test, which spawns the real CLI and is gated so it cannot spend money in CI.

Listed rather than hidden

  • The usage view only sees what kantan's own runs reported — there is no command that asks Claude for a rate limit, so between runs it tells you what it last saw and when.
  • A second Claude account has to be named by hand once. kantan finds the folders but will not guess whether one bills as personal or work.
  • src/run.ts is 2,695 lines of one state machine. Measured, not excused: 34 of its 67 functions mutate the same object.
  • One 731 KB JS bundle, no code splitting. Fine on loopback, which is the only place it runs.
  • It has only ever been run on one machine. A clone-build-run elsewhere has not happened yet.
